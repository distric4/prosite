# План миграции сайта на чистый HTML

> Цель: уйти с выгрузки Tilda (хрупкий минифицированный JS + патчи) на свой лёгкий статический сайт, который легко расширять новыми страницами. Хостинг, домен и приём заявок не меняем.

## Что есть сейчас (точка А)
- 6 страниц — **выгрузка Tilda 1-в-1**. `index.html` весит **1,4 МБ** (внутри инлайн Tilda-JS), остальные 250–420 КБ.
- `assets/` = **14 МБ**: из них реального контента — тексты + ~50 картинок (скрины работ, лого, фото) + 5 шрифтов (woff) + 1 видео.
- Остальное — **балласт Tilda**: 50 JS-файлов и 25 CSS-таблиц, плюс патчи (сторож «Made on Tilda», перехват форм, вшитые иконки). Всё это выбрасываем.

## Куда идём (точка Б)
Статический сайт на генераторе **Eleventy (11ty)**: пишем шапку/подвал/меню **один раз**, 11ty собирает из шаблонов обычные статические HTML. На выходе — чистый HTML/CSS/JS, никакого рантайм-фреймворка и наследия Tilda.

**Почему 11ty, а не «просто HTML-файлы»:** главная боль, из-за которой мы это затеяли — дублирование шапки/подвала/меню в каждом файле («поменял телефон — правь везде»). 11ty решает это через layout + partials + файл данных. При этом результат остаётся 100% статическим для GitHub Pages. Как навык для портфолио — тоже плюс.

**11ty — это НЕ CMS.** Нет сервера, базы и админки «мышкой». Это программа-сборщик: один раз склеивает шаблоны в готовые HTML-файлы. Редактируем в коде (так и работаем). Tilda — CMS; 11ty — заранее «напечатанное меню».

**Сборку автоматизируем через GitHub Actions.** Пушим исходники из `src/` → GitHub сам запускает 11ty и публикует результат. Ручного шага сборки нет, дубли `src`+`docs` в репозитории не коммитим. (Решение зафиксировано: редактирование — в коде, деплой — авто.)

### Целевая структура репозитория
```
src/
  _includes/
    base.njk              // общий каркас: <head>, подключение CSS/JS, header, footer
    partials/
      header.njk          // шапка + меню (один раз на весь сайт)
      footer.njk          // подвал
      form-quiz.njk       // формы как переиспользуемые блоки
      form-lead.njk
      form-audit.njk
  _data/
    site.json             // ЕДИНАЯ точка правды: телефон, почта, @telegram, домен, соцсети
    tariffs.json          // тарифы данными (цены, что входит)
    works.json            // кейсы данными (картинка, заголовок, результат)
  styles/
    tokens.css            // цвета (#00af92), шрифты (Druk Wide, Manrope), отступы
    base.css              // типографика, сетка
    components.css        // кнопки, карточки, формы
  js/
    main.js               // меню, маска телефона, отправка форм → Web3Forms
  assets/
    img/                  // только нужные картинки, пережатые
    fonts/                // 5 woff
  index.njk  works.njk  contacts.njk  blog.njk  privacy.njk  404.njk
.eleventy.js              // конфиг сборки
package.json
docs/                     // ← СЮДА 11ty собирает готовый сайт (его отдаёт GitHub Pages)
CNAME  .nojekyll
```

## Принцип безопасной миграции
Новую версию собираем **параллельно**, в `src/` → `docs/`. Старые файлы в корне продолжают работать на `diasite.ru` всё время сборки. Переключаем GitHub Pages на папку `docs/` **только когда новая версия готова и проверена** → ноль простоя. Старые тильдовские файлы удаляем в самом конце.

Работаем в **отдельной ветке** `rebuild`, в `main` вливаем готовое.

## Этапы

### Этап 1. Каркас и дизайн-токены
- Поднять 11ty (`package.json`, `.eleventy.js`), настроить вывод в `docs/`.
- `base.njk` — общий `<head>`, подключение своих CSS/JS.
- Вынести **шапку, подвал, меню** в partials; телефон/почту/соцсети — в `site.json`.
- `tokens.css` — зафиксировать цвета, шрифты (Druk Wide, Manrope), отступы.
- Собрать пустую `index` со сквозными шапкой/подвалом. Проверить локально (`npx @11ty/eleventy --serve`).
**Результат:** работающий каркас, меняешь телефон в одном месте — меняется везде.

### Этап 2. Перенос контента главной (блок за блоком)
Переносим 1-в-1 по смыслу и визуалу, сверяясь со старым сайтом как эталоном:
Hero → Подход → Работы → Тарифы → Аудит → Сопровождение → Контакты.
- Реальные тексты (заодно правим опечатки из TODO: «АНАЛИТКА», «Предлоагаю», «декстоп», «беджики»; убираем протухшую акцию «до 30 августа 2026»).
- Тарифы и кейсы — в `_data/*.json`, шаблон рисует карточки циклом.
**Результат:** главная визуально = старой, но на чистом коде.

### Этап 3. Формы (свой чистый обработчик)
- `main.js`: меню, маска телефона, валидация, **submit → Web3Forms** (тот же ключ `cf3863c7-...`, та же почта).
- Никаких тильдовских патчей, сторожей и перехвата кликов — формы теперь нативные, пишем их сами.
- Проверить, что заявки реально доходят на почту.
**Результат:** формы работают, кода — десятки строк вместо мегабайта.

### Этап 4. Остальные страницы
- `works`, `privacy`, `404` — перенести.
- `contacts` — **дозаполнить** (мессенджеры текстом, город, форма) — сейчас почти пустая.
- `blog` — решить: наполнить (есть статьи на VC) или убрать из меню (сейчас пустой «Feed not found»).

### Этап 5. Картинки и шрифты
- Перенести в `assets/img` **только используемые** картинки (не весь дамп Tilda).
- Пережать, webp где можно, добавить `loading="lazy"`.
**Результат:** вместо 14 МБ — несколько МБ, сайт быстрее.

### Этап 6. SEO (что давно надо)
- `canonical` / `og:url` → `diasite.ru` (сейчас всё ещё указывают на `alekseydianov.tilda.ws`).
- `title` / `description` под каждую страницу.
- `sitemap.xml`, `robots.txt`, schema.org (Person / LocalBusiness — Иркутск).

### Этап 7. Деплой и переключение
- Добавить workflow GitHub Actions (`.github/workflows/build.yml`): на push собирает 11ty и публикует через GitHub Pages (Source → GitHub Actions).
- Проверить `CNAME` (`diasite.ru`), домен, SSL, формы на бою (Ctrl+F5).
- Удалить/заархивировать старые тильдовские файлы из корня.
- Рабочий цикл дальше: правим `src/` → `git push` → сайт пересобирается сам.

### Этап 8. Документация
- Обновить `CLAUDE.md` под новую архитектуру.
- Короткий README: как собрать и **как добавить новую страницу** (ровно это ты хотел — расширять легко).

## Как добавить страницу ПОСЛЕ миграции (ради чего всё)
1. Создать `src/услуга-X.njk`, в начале указать `layout: base.njk` и заголовок.
2. Написать контент блоками (шапка/подвал подтянутся сами).
3. `git push` → 11ty соберёт, GitHub Pages опубликует.
Никакого копирования тильдовского JS, сторожей и патчей.

## Риски и как снимаем
- **Потерять контент/вид при переносе** → переносим поблочно, сверяясь со старой версией как эталоном; старый сайт живёт до самого конца.
- **Сломать живой сайт** → собираем параллельно в `docs/`, Pages переключаем в последний момент.
- **Node 19 и инструменты** → 11ty v3 работает на Node 18+, наш Node 19.9 подходит.

## Оценка объёма
Это не «пара часов»: самый большой кусок — Этап 2 (перенос и перепроверка главной) и Этап 3 (формы). Делаем поэтапно, после каждого этапа — рабочая проверяемая версия, не ломая прод.
